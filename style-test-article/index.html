    Quick answer

    FIX: "App not installed" on sideloaded APKs is almost always a stale signature conflict — uninstall the old copy (keep data via ADB), then reinstall.

    1. Uninstall the old app: adb uninstall -k com.example.app (keeps data) — or long-press → Uninstall if you don't need data.
    2. Confirm arch + Android version match the APK (arm64-v8a, minSdk ≤ your version).
    3. Reinstall: adb install app-release.apk and read the real error if it fails.

    ⏱ ~6 min · Difficulty: Easy · Applies to: Android 12–14, sideloaded APKs

    Why it happens

    Android refuses the install and shows one useless toast. The Package Manager log always names the real cause — signature mismatch beats corrupt downloads 9 times out of 10.     Symptoms

    • "App not installed" with no error code — classic signature conflict.
    • Install dies at ~90% — storage or split-APK issue:
      • Check free space (need 2× APK size).
      • Check if the file is .apks/.xapk (needs Split Installer, not plain install).
    • Play Protect blocks silently — toggle to confirm, then re-enable.
    1. Reproduce the failure once (note the exact screen).
    2. Pull the truth from logcat (next section).
    3. Apply the fix matrix in order — stop at the first green install.

    The log never lies

    "If the toast says nothing, adb logcat says everything. Read the install lines before you download a fourth copy of the same APK."

    — G-will, after fixing the same Tecno Spark issue twice in one week.

    Pull the failure signature:

    adb logcat -c && adb install app-release.apk
adb logcat -d | grep -i "packageinstaller\|install_failed" | tail -n 20
    Log line containsMeaningFix
    INSTALL_FAILED_UPDATE_INCOMPATIBLEOld copy signed with a different keyadb uninstall -k then reinstall
    INSTALL_FAILED_INSUFFICIENT_STORAGENo room (needs ~2× APK)Free space, clear cache
    INSTALL_PARSE_FAILED_NO_CERTIFICATESCorrupt/incomplete downloadRe-download, check SHA-256
    INSTALL_FAILED_TEST_ONLYDebug APK flagged test-onlyadb install -t or use release build

    Inline code for the road: run adb shell pm list packages | grep example to confirm the ghost copy is really gone.

    The 3-minute fix

    Warning: adb uninstall WITHOUT -k wipes app data. Keep the -k flag if chats, logins, or game saves matter.

    Note: Play Protect re-enable after testing. Leaving it off for "faster installs" is how spyware earns a living.

    Play Protect blocked it — now what?

    Turn it back on after the test install. A blocked sideload that installs fine with Protect off is untrusted until proven otherwise — verify the SHA on the source site.

    Are split APKs (.apks) broken?

    No — they're multi-file by design. Install with Split APK Installer or adb install-multiple base.apk config.arm64.apk.
